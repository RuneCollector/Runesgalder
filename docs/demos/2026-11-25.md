- Local build: 0 warnings, 0 errors.
- Local tests: 206 passed, 0 failed, 8 Docker-gated skipped (Flow 94, MCP 62 + 3 skipped, Sandbox 45 + 5 skipped, Demo 5). Docker is unavailable on this machine, so this is unchanged from the previous record.

## What changed

- `.github/workflows/ci.yml` gains a `linux-e2e` job: publish the worker, build the `runesgalder-worker:dev` image from the worker Dockerfile, verify the image exists, then build and test the solution. On that runner the eight Docker-gated tests run instead of skipping.
- The lane duplicates the solution test run rather than filtering projects, so the container path stays in one job and Demo E2E runs on Linux as well.
- The image check step makes a tag mismatch fail loudly instead of silently skipping the Docker tests.

## What did not change

- No source, test, or runtime behaviour changed.
- The Ubuntu and Windows `build-test` jobs are unchanged; they still skip the Docker-gated tests, which is expected where the image is not built.
- The journal, MCP surface, error codes, and formatting rules are untouched.

## Risks and limitations

- The Docker-gated tests have never run on this machine; their first real execution is the new lane, so the first run may surface container-specific failures.
- `security/escape-corpus/` is still empty; the lane exercises the five existing escape checks in `EscapeTests.cs`, not corpus cases.
- Container coverage is one runner image and one kernel; other runtimes and kernels remain out of scope for now.
