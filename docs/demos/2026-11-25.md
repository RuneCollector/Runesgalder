## Container output directory permissions (same day, after the first lane run)

The first Linux E2E run executed the Docker-gated tests instead of skipping them (MCP 65 tests, 0 skipped; Sandbox 50 tests, 0 skipped) and caught a real defect: five tests failed because the worker, running as the image's non-root user, could not write `result.json` into the host-mounted output directory (`Access to the path '/out/result.json' is denied.`). Docker Desktop had masked this by mapping mount ownership; a native Linux daemon does not.

### Commands and results

```bash
dotnet build Runesgalder.sln -c Release
dotnet test tests/Runesgalder.Sandbox.Tests/Runesgalder.Sandbox.Tests.csproj -c Release --no-build
dotnet format Runesgalder.sln --verify-no-changes
```

- Build: 0 warnings, 0 errors.
- Sandbox tests locally: 46 passed, 5 Docker-gated skipped, 0 failed (one new permission test).
- Format: clean for the whole solution.

### What changed

- `SandboxContainerRunner` prepares the output directory on Unix by granting group and other write and execute, without granting list access. The worker keeps its non-root image user; the directory holds untrusted output by design.
- `ContainerRunnerTests` pins the resulting mode on Unix and is a no-op on Windows.

### What did not change

- Container flags are unchanged: still non-root, read-only root, `cap-drop ALL`, `no-new-privileges`, no network, tmpfs `/tmp`.
- The MCP error mapping is unchanged; the earlier `sandbox_unavailable` responses were a symptom of the missing result file.

### Risks

- Output directories become writable by other local users on Unix hosts. Runs are per-run temporary directories and shared hosts are already discouraged; the directory still denies listing.
- The fix is exercised for real only by the Linux lane; Docker remains unavailable on this machine.

The fix re-run is green on every lane: Flow 94, Demo 5, MCP 65, Sandbox 51, all with 0 skipped, including the five escape checks and the three MCP container tests that had never executed before. Commit `cb6adc7`.

### What changed

- ADR-0014 is now implemented: `SandboxDiagnostics` holds the public source and tag names, `SandboxMetrics` owns the eight instruments, `ScriptCompiler` emits `compile csharp`, and `RunManager` emits `sandbox run` with limits, outcome, exit code, kill reason, and used resources. `docs/observability.md` documents the spans, instruments, tag vocabularies, and the stdio trace-context limitation.
- `security/escape-corpus/` is populated: eleven non-destructive cases in `cases.json` with per-case `Source.cs`, and a Docker-gated data-driven test, `EscapeCorpusTests`, that asserts each expected outcome and summary.
- A second MCP client, `RawJsonRpcClientTests`, speaks newline-delimited JSON-RPC directly, so the stdio surface is verified by the official SDK client and by an independent hand-written client.
- English, Chinese, and German quickstarts cover prerequisites, one-command worker image, MCP publish, a client configuration snippet, and troubleshooting. `scripts/sandbox-up.sh` and `.ps1` build the worker image.
- The version is centralised in `Directory.Build.props`; `McpOptions.ServerVersion` derives from the assembly informational version. `CHANGELOG.md` and `.github/workflows/release.yml` prepare a tag-driven release with source-built zips, `SHA256SUMS`, the GitHub dependency-graph SPDX SBOM, and build-provenance attestations.
- `README.md` links the site and the quickstarts; the eight 2026-11-24 dependency merges are backfilled into that day's demo record.

### What did not change

- No package is published; the release attaches source-built archives only.
- Telemetry remains off by default and records no payloads, paths, or run identifiers on metrics.
- Container flags, journal semantics, and the MCP tool surface are unchanged.

### Verification limits

- The Docker-gated corpus and container tests still skip on this machine; the Linux E2E lane is their first real execution.
- End-user MCP clients were not exercised here: the local Claude Code configuration is pinned to an unavailable model (`unrecognized_model`) and Cursor has no headless CLI. Two independent stdio client implementations pass locally, and the CHANGELOG states this rather than claiming application-level verification.

### Risks

- The new `sandbox run` span uses the error-code vocabulary from the envelope; a future rename needs a new ADR, as the document requires.
- Release assets depend on GitHub's dependency-graph SBOM being available at tagging time; the workflow fails rather than publishing without it.
