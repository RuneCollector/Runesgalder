## Finding: compilation is not the isolation boundary

A file-based probe against .NET 10.0.12 shows where the entry points actually live:

```
System.Private.CoreLib      (typeof(object))
System.Private.CoreLib      (typeof(System.IO.File))
System.Diagnostics.Process  (typeof(System.Diagnostics.Process))
```

`System.IO.File` is in `System.Private.CoreLib`, so removing `System.IO` from the reference whitelist cannot prevent file access. The banned-namespace scan is defence-in-depth and a diagnostic aid only; real enforcement is the runtime isolation tier from ADR-0004. This is recorded in ADR-0006.

## Dependency added

`Microsoft.CodeAnalysis.CSharp` 5.12.0 — needed for the compile pipeline; MIT licence (Microsoft); runs on the host against untrusted source, so source size is capped and the compile step is scheduled to move behind the execution boundary. Review in ADR-0006.
