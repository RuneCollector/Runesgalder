## Build and test

- Build: succeeded with 0 warnings and 0 errors.
- Tests: 37 passed, 0 failed.
  - `KeepsThePrefixWhenTheSuffixFails` — a later step failing does not discard the checkpointed prefix; the rerun restores it, skips the prefix, and re-runs the suffix.
  - `DoesNotStoreACheckpointWhenThePrefixFails` — a failed prefix leaves no checkpoint; the next run repeats the work and then stores it.
  - `DoesNotStoreACheckpointWhenThePrefixIsCancelled` — a cancelled prefix leaves no checkpoint.
  - `DoesNotPersistACheckpointForAFailedRun` — the same promise holds for `SqliteJournal` after reopening the file.
  - `PreservesEveryEventWhenWritersAppendConcurrently` (memory and sqlite) — four writers interleave 100 events across four runs; every event survives and each writer's order is intact.
  - `KeepsTheFirstCheckpointWhenWritersRaceForOneKey` (memory and sqlite) — twenty racing saves for one key settle on a single stored value.

## What changed

- Three checkpoint recovery tests pin the invariant "a checkpoint means the prefix completed".
- Two journal concurrency tests pin the invariant "interleaved appends lose nothing and keep per-writer order", for both `InMemoryJournal` and `SqliteJournal`. This is the property FanOut branches will rely on.
- `TempDirectory` moved from `SqliteJournalTests` into shared test infrastructure because a second test file now needs it.

## What did not change

- No public API, journal schema, event kind, or error code changed.
- `SqliteJournal` remains scoped to a single writer process; the per-append gate serialises writers inside that process.

## Risks and limitations

- Concurrency is exercised within one process; cross-process writers remain out of scope for schema v1.
- The tests assert per-writer order, not a global total order, which matches the journal contract.
