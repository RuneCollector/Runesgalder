## What changed

- Three checkpoint recovery tests pin the invariant "a checkpoint means the prefix completed".
- Two journal concurrency tests pin the invariant "interleaved appends lose nothing and keep per-writer order", for both `InMemoryJournal` and `SqliteJournal`. This is the property FanOut branches will rely on.
- Eleven compiler refusal tests pin the banned-namespace check across all eight namespaces and three bypass spellings (alias, static import, `global::`).
- `TempDirectory` moved from `SqliteJournalTests` into shared test infrastructure because a second test file now needs it.

## What did not change

- No public API, journal schema, event kind, or error code changed.
- `SqliteJournal` remains scoped to a single writer process; the per-append gate serialises writers inside that process.

## Risks and limitations

- Concurrency is exercised within one process; cross-process writers remain out of scope for schema v1.
- The tests assert per-writer order, not a global total order, which matches the journal contract.

## Flow combinators (same day, after acceptance)

ADR-0011 was accepted and the four missing combinators landed the same day: `Branch`, `FanOut` (with `Then` as FanIn), `Flow.Timeout`, `Step.Timeout`, plus `Fallback` and the `Retry` predicate. One new stable error code, `flow.timed_out`; no new journal event kinds.

### Example

```csharp
var flow = Flow.Start(Step.Define<string, int[]>("load", LoadRowsAsync))
    .Timeout(TimeSpan.FromSeconds(30))
    .FanOut(
        Step.Define<int[], int>("sum", ComputeSumAsync),
        Step.Define<int[], int>("median", ComputeMedianAsync))
    .Then(Step.Define<int[], string>("report", FormatReportAsync))
    .Fallback(Step.Define<string, string>("cached", UseCachedReportAsync));

var retrying = Flow.Start(Step.Define<int, int>("call-model", CallModelAsync))
    .Retry(3, exception => exception is TimeoutException);
```

### Behaviour pinned by the new tests

- Branch: only the chosen step emits lifecycle events; a throwing predicate fails the run with no branch executed; the flow name records `prefix ? true : false`.
- FanOut: branches overlap in time; results keep declaration order even when a later branch finishes first; a failure cancels siblings; the earliest declared failure is the one rethrown; caller cancellation wins and ends the run as `flow.cancelled`; empty and null branch lists are rejected.
- Timeout: expiry throws `TimeoutException` naming the flow or step and journals `flow.timed_out`; `Step.Timeout` emits one `StepStarted`/`StepFailed` pair; caller cancellation wins and journals `flow.cancelled`; zero, negative, and infinite deadlines are rejected.
- Fallback: the alternative sees the original input; filtered failures rethrow; caller cancellation bypasses the fallback; both failures surface as `AggregateException(primary, fallback)`; a throwing filter fails the run.
- Retry: only matching failures are retried; non-matching failures rethrow without `StepRetryScheduled`; a throwing predicate fails the run; cancellation never retries.

### What did not change

- Journal schema stays v1; no new event kinds.
- `Retry(int, TimeSpan)` keeps its behaviour and now delegates to `Retry(int, Func<Exception, bool>, TimeSpan)` with `static _ => true`.

### Risks

- Deadlines are cooperative: a step that ignores its token can overrun.
- Fan-out branches share one journal; keep branch names unique for readable transcripts.

## Budgets and approvals (same day, after acceptance)

ADR-0012 was accepted and implemented the same day: shared `Budget` and approval types, four journal events, `Flow.Budget`, and `Flow.RequireApproval`, with explicit token and USD charging on `FlowContext`. Two new stable error codes, `flow.budget_exceeded` and `flow.approval_denied`; no schema change.

### Example

```csharp
var flow = Flow.Start(Step.Define<string, string>("report", GenerateReportAsync))
    .RequireApproval(approver, "flow.run", "Generate the weekly report", TimeSpan.FromMinutes(2))
    .Budget(new Budget
    {
        MaxTokens = 20_000,
        WarnTokens = 15_000,
        MaxUsd = 0.50m,
        MaxWall = TimeSpan.FromMinutes(1),
    });

// Inside a step, after a model call returns:
await context.ChargeTokensAsync(usage.InputTokens + usage.OutputTokens, cancellationToken);
await context.ChargeUsdAsync(hostPriceTable.Cost(usage), cancellationToken);
```

Because the approval wrapper sits outside the budget wrapper, the approval wait counts against `MaxWall`; reversing the two calls excludes the wait.

### Behaviour pinned by the new tests

- Budget: wall expiry appends `BudgetExceeded(Wall)` and ends the run as `flow.budget_exceeded`; a token or USD crossing fails at the charge with `Limit` and `Used` on the exception and on the event; each dimension warns once per scope; a wall warn appends an advisory event without failing the run; charges without a budget are no-ops; nested scopes charge innermost first and the first trip decides; an inner scope ends when its segment returns; caller cancellation wins and journals `flow.cancelled` with no `BudgetExceeded`; invalid budgets and negative charges are rejected.
- Approval: approval journals the request, the resolution, then the segment; denial fails with `flow.approval_denied` and the segment never runs; timeout resolves `TimedOut` and denies; an approver that returns `TimedOut` is treated as a denial; caller cancellation writes no resolution; approver exceptions propagate unchanged; zero, negative, and infinite timeouts are rejected.
- Journals: the four new events round-trip through `SqliteJournal`, including `BudgetDimension` and `ApprovalDecision` as strings.

### What did not change

- Journal schema stays v1; the new event tags are additive and older readers keep rejecting unknown tags.
- No new dependency; approvals need a host-implemented `IApprover`, and there is no built-in interactive prompt.

### Risks

- Token and USD totals depend on host adapters charging correct values; the runtime never infers cost from `ModelCallCompleted`.
- An approver that ignores its cancellation token can hold the run past the timeout.
- Budget scopes follow the asynchronous execution context: a budget attached inside one fan-out branch does not govern its siblings, while an enclosing budget governs every branch.

## Metrics and governance attributes (same day, after acceptance)

ADR-0013 was accepted and implemented the same day: a BCL `Meter` alongside the existing `ActivitySource`, eight instruments, governance span attributes, and a `docs/observability.md` follow-up. No new dependency; telemetry remains off unless a host registers the source and meter.

### Example

```csharp
// Host side, once:
builder.Services.AddOpenTelemetry()
    .WithTracing(tracing => tracing.AddSource("Runesgalder.Flow"))
    .WithMetrics(metrics => metrics.AddMeter("Runesgalder.Flow"));
```

```csharp
// A denied approval now leaves both a journal record and a countable metric.
var flow = Flow.Start(Step.Define<string, string>("report", GenerateReportAsync))
    .RequireApproval(approver, "flow.run", "Generate the weekly report", TimeSpan.FromMinutes(2));

// Runs emit flow.runs{flow.name, flow.outcome};
```
