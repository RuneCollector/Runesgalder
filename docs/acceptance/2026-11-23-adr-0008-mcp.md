## Scope

- New executable `runesgalder-mcp` over stdio; stdout carries protocol frames only, logs go to stderr.
- Tools: `compile_csharp`, `run_csharp`, `get_run`, and `cancel_run`.
- v0.1 executes only the analysis contract (`IAnalysis`, `ITable`, `IScriptContext`) with inline CSV; no file paths, no general console entry point.
- One run at a time, queue of four, in-memory results retained 30 minutes after a terminal state and capped at 100 runs.
- Dependency: `ModelContextProtocol` 2.4.0 (Apache-2.0) with pinned `Microsoft.Extensions.*` 10.0.x.

## Evidence

- Build: not applicable at decision time; the ADR is a design record.
- Tests: plan covers handler units with a fake runner and one Docker-backed integration test per lane.
- Demo: implementation and stdio smoke transcript will be recorded in `docs/demos/2026-11-23.md`.
- Security review: the server launches the existing hardened container and accepts no host paths, URLs, environment variables, secrets, or Docker options from clients. Docker access is never exposed as a tool.
- Secret scan: the reviewed change is documentation only; no credentials or machine-specific paths were added.

## Risks

- Long analyses depend on the client's timeout; polling with `get_run` is the reliable path.
- One run at a time caps throughput; a daemon with queueing remains future work.
- Results are lost when the server exits; durable runs need journal integration.
- The pinned SDK is a new dependency; upgrades must be retested against the client smoke set.
